# Данные и код к статье «Больше розницы, не меньше эффективности»

Репликационный пакет к статье о краткосрочной эффективности российского рынка
акций после 2022 года (журнал «Деньги и кредит» / Russian Journal of Money and
Finance). [English version](README.en.md).

Репозиторий: <https://github.com/quantviews/efficiency-paper-2026>.

Один скрипт, ноль настройки:

```bash
pip install numpy pandas
python replicate.py --check
```

## Что здесь есть и чего нет

Исходные данные - полный журнал заявок и сделок Московской биржи за 2021–2025
годы по 60 акциям: около 2,4 ТБ архивов. Распространять их нельзя, доступ
определяется условиями биржи. Но между ними и всеми выводами статьи лежит один
узкий слой - **панель тикер-дней в 5 732 строки**, и он здесь есть целиком.

| шаг | где | воспроизводится |
|:--|:--|:--|
| журнал заявок → книга → снимки на сетке | у авторов | нет, данные лицензированы |
| снимки → показатели тикер-дня | `replicate.py --example` | на синтетическом дне |
| показатели → таблицы, интервалы, регрессии, выводы | `replicate.py` | полностью |

Третья строка - это почти вся статья: средние по периодам, разности «до/после»,
доверительные интервалы блочным бутстрапом по датам, регрессии с фиксированными
эффектами бумаг, разбивка по группам ликвидности и секторам, тренд внутри
пост-периода, торговая проверка, тесты структурного сдвига.

Вторая строка проверяется на синтетическом дне с **заданными** свойствами:
середина котировки идёт случайным блужданием, спред постоянен, сторона сделки
выбирается независимо. Оценки должны эти свойства восстановить: VR(5) средней
котировки около единицы, автокорреляция цен сделок отрицательна, оценка Ролла
близка к заданному спреду, а VR(5) микроцены уходит ниже единицы - шум очереди,
которого в средней котировке нет. Реальные снимки книги в пакет не входят: это производное от данных
биржи.

### Колонки панели

`ticker`, `date`, `period` - бумага, торговый день, период выборки.
`n_obs` - число снимков книги, по которым посчитан день.

| колонка | что измеряет |
|:--|:--|
| `vr5_mid`, `vr30_mid` | дисперсионное отношение средней котировки, лаги 5 и 30 шагов |
| `vr5`, `vr30` | то же на взвешенной средней котировок (микроцене) |
| `vr5_z`, `vr30_z` | робастный к гетероскедастичности z (Lo, MacKinlay, 1988, M2) |
| `vr25s`, `vr25s_mid` | дисперсионное отношение на фиксированном горизонте 25 с |
| `ac1_mid`, `ac1_micro` | автокорреляция приращений на лаге 1 |
| `ac1_trade` | то же для цен сделок: в них живёт бид-аск отскок |
| `roll_spread_bps` | эффективный спред по Roll (1984); пусто, если оценка не определена |
| `quoted_spread_bps` | медиана котируемого спреда за день, б.п. |
| `ofi_r2_60s`, `ofi_r2_300s` | доля дисперсии будущей доходности, объяснённая дисбалансом потока заявок |
| `realized_vol_bps` | реализованная волатильность за день, б.п. |
| `turnover` | оборот, лотов |

Пустая ячейка означает «оценка не определена», а не ноль. Это существенно для
`roll_spread_bps`: подстановка нуля занижала бы средний спред.

### Код

- `replicate.py` - весь расчёт. Зависимости: `numpy`, `pandas`; для `--figures`
  дополнительно `matplotlib`. Кода авторского исследовательского пакета не
  использует: это независимая реализация, и совпадение чисел поэтому
  что-то значит.

```bash
python replicate.py             # таблицы 2-7 статьи
python replicate.py --check     # сверка с опубликованными числами
python replicate.py --example   # расчёт показателей из снимков книги
python replicate.py --figures   # + рисунки
```

## О доверительных интервалах

Точечные оценки детерминированы и обязаны совпадать с опубликованными знак
в знак. Границы интервалов и p-значения - случайные величины: бутстрап здесь
запускается со своим генератором на каждую величину, а не одним потоком
случайных чисел на весь отчёт, как в исходном расчёте. Поэтому `--check`
сверяет точечные оценки строго, а p-значения с допуском в четыре стандартные
ошибки бутстрапа: при p около 0,7 его шум втрое больше, чем при p = 0,05, и
круглая константа была бы то слишком мягкой, то слишком жёсткой. Если выводы
статьи зависели бы от конкретной последовательности розыгрышей, это было бы
видно именно здесь.

## Как устроен бутстрап

Ресемплируются **даты целиком**, а не отдельные тикер-дни. Наблюдения одного дня
несут общий рыночный шок; ресемплинг строк разрушал бы эту зависимость и давал
слишком узкие интервалы. Дат в выборке 105 при 5 732 строках, разница
существенна. Число повторений B = 4000, сид 12345 - оба в `data/efficiency.yaml`.

Нижняя граница p-значения - 1/(B+1): бутстрап не может дать ноль, и «p = 0,000»
создавало бы видимость невозможного события.

```bash
sha256sum -c CHECKSUMS.sha256
```
